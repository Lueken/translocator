Annotations

1Custom titlebar. Ink-dark bar replaces the OS chrome (the black Windows bar currently clashes with the leaf). Gear + wordmark left, drag region middle, min/max/close right; close hollows to oxblood on hover. The drawn-X animation you liked in SF slots here later.
2Play dock. The selected installation + Play pinned at the sidebar's foot, so you can launch from any screen without navigating back. (The one VSL pattern worth keeping: their bottom-left dock.)
3Status strip. Filter box + counts by compatibility, so 191-mod packs stay navigable. Counts double as the legend, so the separate legend row goes away (one less thing to mismatch).
4Grouped register. "Ready to update" and "Held back, needs a newer game" as ruled section heads. Your yellow-bucket instinct from VSL, done as ledger sections; held-back rows sit dimmed at the bottom, never mixed in.
5Row overflow (⋯). Ignore this version / Pin this mod / Open mod folder. Curators hold mods back on purpose: an ignored version stops appearing until the next release. Also where rare actions live so rows stay clean.
6Span note. When the jump crosses several releases, the folio says so explicitly: updating applies every entry between installed and target. Makes the read-the-notes behavior the default mental model.
7Toasts with Undo. Feedback appears where you acted, not in a log buried in Settings. Undo reinstalls the previous version. The Activity log stays in Settings as the forensic record.
8Backup caption under Update-all, exactly where you moved it. The banner container is gone for good.
9Determinate progress. The check emits per-mod progress from the backend; the bar + "128/191" replaces the current silent 5-second freeze. Skeleton rows hold the layout.
10Empty state with a voice. "Every entry is current" + last-checked time: a confident resting state instead of a bare sentence.
11Confirm the destructive action. Restore replaces the whole Mods folder, so it gets a modal that states what happens, when the snapshot is from, and that it's undoable (because we back up first).
12Copy update report. One click exports pending updates + changelogs as markdown. That is your exact Quire curation flow (vet per domain, paste to Discord/brief) built into the tool. Nobody else has this.

Benchmark: CurseForge (the industry standard, not the template)

✓Learn: metadata-dense rows. Their Browse rows carry downloads · updated date · file size · game version · loader as scannable chips. Our Mods view should show downloads · last release · compatible game versions per result. The data is already in the ModDB response.
✓Learn: Import is a first-class action. "Create / Import" sit at the top of My Modpacks. When our manifest modpacks land, Import a pack file must be one click on Installations, not buried.
✓Learn: version badge on every card. Each pack card wears its version. Our installations should wear game version + mod count the same way (the Play dock already does).
✗Avoid: the ad rail. A quarter of their window is ads; "Ads support authors. Subscribe" is the business model bleeding into the chrome. Translocator's answer is structural: no ads, no subscriptions; the ♥ tip button routes support straight to authors. That's a trust feature; say it in the app's About.
✗Avoid: icon-only mystery rail. Their left rail is nine unlabeled icons, the exact VSL sin you flagged. Our index stays worded, always.
✗Avoid: sponsored rows in results. Their Browse mixes paid "Sponsored" packs (with a fake Play button) into search results, and Discover leads with contests over content. Ranking in Translocator is never for sale; results order is always explainable (downloads, updated, relevance).
✗Their gap, our edge: even the industry standard shows no release notes in its update flow; "Update" is a blind button there too. The changelog ledger remains the feature nobody else has.

Implementation checklist

  • Window basics first: set minWidth/minHeight (≈960×640) in tauri.conf.json to kill the broken narrow layout outright, and add tauri-plugin-window-state so size/position persist.
  • Custom titlebar: decorations: false + a drag-region header component; min/max/close via the window API. Do this when ready; it's cosmetic, not blocking.
  • Progress events: check_updates emits (done, total) via a Tauri channel as each mod resolves; frontend renders the bar. Backend loop already iterates per-mod, so it is one emit line.
  • Toast + Undo: small toast stack in React; Undo = install_release of the previous version (we know it; it's the version we just replaced).
  • Confirm dialog for Restore; take an automatic safety backup before restoring so the modal's "undoable" claim is true.
  • Grouping + filter + sort: pure frontend over the existing ModUpdate[]: compatible/should-work first, held-back section last, text filter on name/modid.
  • Ignore/pin list: persist {"{modid: version}"} per installation (same pattern as the account store); filter ignored versions out of check_updates results.
  • Update report: serialize pending updates + changelogs to markdown, copy to clipboard (tauri-plugin-clipboard-manager).
  • Display names: render folder names with hyphens/underscores as spaces ("The-Quire" → "The Quire"); keep the raw name everywhere paths matter.
  • Native select: the OS-drawn option list resists theming; if it still clashes after the opaque fix, replace with a small custom dropdown (also gives the install picker its verdigris status dots).
